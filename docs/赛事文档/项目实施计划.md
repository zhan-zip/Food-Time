## P2 — 特色功能（差异化竞争力）

### P2-1 DIY 拖拽烹饪（方案 C：双开门冰箱 + 岛台）

**最终设计方案**（2026-07-24 讨论确定，详见 `food-time-project-summary.md` 第二十一节）：

#### 设计理念

模拟真实厨房体验：打开冰箱选食材 → 放到岛台备菜盘 → AI 建议 → 烹饪动画 → 保存/分享。

#### 页面布局

```
┌─────────────────────────────────────────────────────────┐
│                    我的厨房                               │
├────────────────────────┬────────────────────────────────┤
│                        │   📋 已选食材（备菜盘）           │
│  🧊 双开门冰箱          │   [🥩猪肉] [🍅番茄] [🧅洋葱] ... │
│  ┌────────┬─────────┐  │                                │
│  │ 🥩 肉类 │ 🥬 蔬菜  │  │       🍳 烹饪岛台              │
│  │ 猪肉    │ 番茄     │  │  ┌─────────────────┐         │
│  │ 牛肉    │ 青椒     │  │  │   🍽️ 备菜盘     │         │
│  │ 鸡肉    │ 土豆     │  │  │                 │         │
│  │ ...     │ ...     │  │  └─────────────────┘         │
│  ├─────────┴─────────┤  │                                │
│  │ 🦐 海鲜 │ 🧈 豆制品│  │   [🤖 获取 AI 烹饪建议]        │
│  │ ...     │ ...     │  │   [清空] [开始烹饪]            │
│  └───────────────────┘  │                                │
│                         │                                │
│ 🧂 调料台（始终可见）     │                                │
│ [盐] [酱油] [醋] [糖] ... │                                │
├────────────────────────┴────────────────────────────────┤
│              🤖 AI 烹饪建议 / 匹配结果面板                  │
└─────────────────────────────────────────────────────────┘
```

#### 组件的三板规格

| 组件 | 关键规格 |
|------|----------|
| **冰箱** | 默认关闭 + "🧊 点击打开冰箱"提示；点击后 CSS `perspective` + `rotateY` 双门打开(0.5s)；左门=肉类+海鲜，右门=蔬菜+豆制品+蛋奶；分区内 `overflow-y:auto` |
| **食材卡** | 64×72px；emoji(24px) + 中文名(12px) + 底部分类色条(4px)；肉类红/海鲜蓝/蔬菜绿/豆制品黄/蛋奶黄/调料灰；无emoji用文字卡片；选中 `scale(1.1)` + 阴影 |
| **备菜盘** | 岛台中央直径200px大圆盘；食材飞入贝塞尔曲线动画(0.4s)；点击可移除；上限10种 |
| **调料台** | 底部横滚抽屉 `overflow-x:auto`；始终可见 |
| **烹饪动画** | 仅步骤④触发：炒锅=火焰跳动+翻炒 / 空气炸锅=热风波纹+倒计时 / 蒸锅=蒸汽升腾消散 |

#### AI 烹饪建议逻辑

```
用户已选食材集合 {猪肉, 番茄, 青椒, 盐}
  → ① 数据库匹配：foods 表搜索 name/ingredients 交集≥2
    → 有结果：展示已匹配菜谱 → 用户可选直接保存
    → 无结果：调用 DeepSeek
  → ② DeepSeek 生成科学烹饪建议(步骤/火候/时间/营养)
  → ③ 用户确认 → 选烹饪方式 → 动画 → 保存
  → ④ 保存：写入 custom_recipes + foods(source='custom')，可选发布到广场
```

## 营养数据准确性增强（方案 A+B）

> **背景**：当前饮食记录基于食材加权平均计算营养，未考虑烹饪过程中油脂吸收、水分蒸发带来的热量变化。为应对评委质询，引入烹饪方式修正系数 + UI 透明标注。

### 方案 A：UI 透明标注

- [x] 饮食记录页面加免责说明：`* 营养数据基于食材加权平均结合烹饪方式修正系数估算`
- [x] 详细设计文档标注算法局限性

### 方案 B：烹饪方式修正系数

- [x] 在 `diet/router.py` 营养计算逻辑中引入烹饪修正系数（`COOKING_FACTORS`，存于 `diet_records.adjusted_calories`）
- [x] 系数参考（源自国内外烹饪营养学研究）：
  - 炒 ×1.20（油脂吸收 15-25%）
  - 炸 ×1.50（大量油脂吸收）
  - 烤 ×1.05（少量油脂流失）
  - 蒸 ×0.95（水分增加）
  - 煮 ×0.90（水溶性营养流失）
  - 炖 ×1.10（汤汁含油）
  - 生/凉拌 ×1.00
- [ ] 蛋白/脂肪/碳水按独立系数修正（如炸的脂肪 ×2.0）——未实现（当前仅对总热量做系数修正，蛋白/脂肪/碳水为食材加权值）

### 评委应对话术

> 以《中国食物成分表》为基础构建食材营养数据库，在此基础上引入烹饪方式修正系数——该系数参考了国内外烹饪营养学研究中关于不同烹饪方式对宏量营养素影响的通用结论。算法在科学性和工程可行性之间取得了平衡。
